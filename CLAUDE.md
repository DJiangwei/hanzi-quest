## What this is

**hanzi-quest** (deployed as `hanzi-adventure.vercel.app`) — a personal Chinese-character learning game for the maintainer David's daughter Yinuo (6yo, UK-based, English-native) and a few friends-and-family kids. Pirate-adventure art direction. Parent authors weekly character lists in an admin panel; AI generates kid-friendly scenes; child plays a multi-level "island" of mini-games per week, with a boss + card rewards.

It is **not** a multi-tenant SaaS. Optimize for the kids' daily fun and actual learning, not for theoretical other users.

## Current state — subsystem snapshot (last refreshed 2026-09-05, through PR #172)

**Play loop.** Home (`/play/[childId]`) shows an illustrated **voyage board** (vertical zigzag on phones, landscape 16:10 at `lg:` via `useIsWide()`) of the current map's weeks. **Islands unlock linearly (T3, 2026-07-26): everything past the frontier is 🔒 until the previous week's boss falls** (server-enforced by `getWeekGateState` on both play routes; an already-beaten week never re-locks). **Only weeks that actually compiled a boss participate** — a week below `BOSS_MIN_CHARS` (**8** since PR #152) is bossless, so `listBossWeekIds` excludes it from the frontier, the key ring, and map completion (PR #151). Map 1 has no such week today: all 10 weeks are bossed (weeks 9+10 teach 8 chars → 8-question gauntlets, capped by `BOSS_MAX_QUESTIONS`). Tapping an unlocked island → **week hub** (`/week/[weekId]`) with 3 sections served at `/level/[weekId]/[section]`: **回顾** (flashcards, ending in a 3-way 认识/不确定/不认识 self-assessment — all three buttons styled IDENTICALLY since PR #168, plus a `revealed` behavioural signal), **练习** (15 practice scenes per 10-char week: 3 audio_pick + 3 image_pick + 1 lianliankan + 2 image_word + 6 meaning; `PRACTICE_SCENE_COUNT=15`), and **Boss战** (locked until 7 practice scenes cleared; 10 bespoke procedural-SVG creatures rotate by weekNumber, phase machine intro→idle→damage→defeat). Active scene types: flashcard, audio_pick, image_pick, image_word, translate_pick, sentence_cloze, lianliankan, boss. **Both boss gauntlets rotate 4 types** (audio_pick + image_pick + translate_pick + sentence_cloze — `visual_pick` dropped 2026-07-27; it served pinyin choices). Retired-but-kept (is_active=false, components remain for old attempts): pinyin_pick, visual_pick, word_match. Scenes are compiled into `week_levels` by `compileWeekIntoLevels` with **stable level keys** (`review:flashcard:<charId>`, `practice:<type>:<slot>`, `boss:boss:0`); compile changes need `scripts/recompile-all-weeks.ts` post-merge. **image_pick stimulus validity (2026-08-23):** the chosen `wordId` is frozen into `scene_config` at compile time (`validStimulusWords`, rejecting words shared with another same-week character or lacking art), and counting characters (一…十) skip diffusion art entirely for a procedural `CountingBalloons` SVG — `scripts/verify-stimulus-integrity.ts` audits the compiled corpus read-only. Powerups: 💡 hint is a free local toggle (practice only, never boss), ⏭️ skip is a paid consumable (skipped scenes score 0 and don't count toward boss unlock), 🧊 streak-freeze auto-burns.

**Learning telemetry & bounties.** `answer_events` (migration 0034, write-only): one row per answered question across practice/review/boss/homework/study with target char/word, correctness, picked wrong choice, and flashcard self-ratings. Its first consumer is **通缉令 wanted bounties (T2, 2026-07-18)**: 3 daily posters on home for unseen/weak characters (unseen-later-weeks first; pure engine `src/lib/bounty/ranking.ts`, storage `bounty_posters` migration 0038, generated idempotently on home render, 3-day cooldown). Correct answers anywhere tick posters via `tickBountyProgress` (guarded, in `finishAttemptAction` after event logging); a full poster (2 hits) claims +40🪙+10XP (`claimBountyAction`); all-3 claimed → a `'bounty'` card (cap-consuming). Feeds the future review loop + parent insights (`docs/IMPROVEMENT-ROADMAP.md` A2/A3/V1).

**温故 Daily mixed review (A2, 2026-09-02).** The second consumer of `answer_events`, after 通缉令 bounties. A pure selection engine (`src/lib/review/selection.ts`) scores every character from a CLEARED week with `reviewScore = weakness + staleness`: weakness blends error rate + `dont_know`/`not_sure` self-ratings (`NEUTRAL_WEAKNESS=20` for a character with no telemetry at all, so pre-2026-07-03 characters can't be excluded), staleness is days since last seen (`STALE_DEFAULT_DAYS=14` when never seen, capped at `STALE_CAP=30`). Deliberately NOT `bountyScore` — bounties rank a never-answered character above every weak one (101+ vs 34 for the same inputs; right for pushing into unvisited weeks, wrong for retention) — a test pins the difference. `pickReviewTargets` takes the top `REVIEW_SESSION_SIZE=6` deterministically (ties break weekNumber desc then hanzi, mirroring `pickBounties`). Questions are built at REQUEST time by `buildReviewSession` (`src/lib/review/session.ts`) — no `week_levels` rows, no compile, no recompile post-merge — rotating `translate_pick`/`audio_pick`/`image_pick` per target, with `buildWordOwners`' ambiguity guard evaluated over the WHOLE cross-week candidate pool (see the landmine). `getReviewSessionData` (`src/lib/db/review.ts`, split from the lighter `getReviewCandidates` for the home-render read) reads only cleared weeks (`week_progress.bossCleared`) in the child's current pack — a week still being taught is practice's job, not 温故's. The home `DailyReviewCard` (📜, hidden entirely below `REVIEW_SESSION_SIZE` candidates — an entry point to an empty session is worse than none) links to `/play/[childId]/review`, which redirects home if there's nothing to review. `finishReviewAction` pays a flat `REVIEW_REWARD_COINS=40`🪙 + `REVIEW_REWARD_XP=15`XP + a `'daily_review'` card (once per UTC day GLOBAL via `pullCardForChild`, same shape as review-section completion) ONLY on the grant's `granted` branch — completion pays, never score, and nothing anywhere gates on 温故 having been played. Logs under a distinct `'daily_review'` answer-event source, migration 0042 (`coin_reason` gains the value).

**航海日志 Logbook & mastery (V1, 2026-09-04).** A pure `masteryForChar` (`src/lib/mastery/mastery.ts`) is now the ONE substrate over `answer_events` for both display and ranking: `evidence = scored + dontKnow` (`scored` = rows with `correct IS NOT NULL`; `got_it` self-ratings are excluded from the denominator entirely — every one of prod's 164 is `got_it`, so counting them let tapped-through flashcards bury a genuinely failed answer), `missRate = (wrong + dontKnow) / evidence` (`null`, never `0`, at zero evidence), and a coarse `state` — `'unrated'` below `MASTERY_MIN_EVIDENCE=3` evidence, else `'proficient'` at `>= PROFICIENT_ACCURACY` (80%), else `'learning'`. **温故 now reads the same function** (its weakness term; `ReviewCandidate.total` renamed `.scored`) — a live dilution fix, since the old `count(*)` denominator let five `got_it` flashcards bury one failed scored answer (17% instead of 100%, a 50-point misranking on a 0–90 scale that flattered exactly the characters she'd drilled most). **航海日志 / Captain's Logbook** (`getLogbookEntries`, `src/lib/db/logbook.ts`) is a Backpack hall card (`LogbookHallCard`, rendered above the 15 collectible pack halls) showing every character from her currently UNLOCKED weeks — deliberately wider than 温故's CLEARED-only pool, since the Logbook shows what she's *learning*, including the week in progress, and reuses the same `listBossWeekIds` + `frontierWeekNumber` + `isWeekUnlockedFrom` trio the home board uses so it can never show a character from a 🔒 island. `LogbookGrid` badges ONLY `熟练` (`学习中` and unbadged entries are visually quiet by design — a badge she hasn't earned is a false signal, a missing one is honest); nothing on the page can ever render a percentage or failure language (test-guarded). Mastery never decays in the Logbook — staleness stays 温故's job. Against prod's 96 characters today: 31 `熟练` / 8 `学习中` / 57 unbadged. No DB column, no migration — computed on read.
